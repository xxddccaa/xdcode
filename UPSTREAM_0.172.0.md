# xdcode 0.172.0 upstream upgrade

Started November 27, 2026. This is an independently maintained derivative of
OpenAI Codex. Attribution and licenses remain in LICENSE, NOTICE and
MODIFICATIONS.md.

## Baseline and method

- Previous product: xdcode `0.167.0` on upstream `rust-v0.165.0`
  (`360319d8dee62d87e2d59fc0c21805d79519cfed`) plus 133 selectively backported
  commits (recorded in the previous `upstream.json`, now under
  `previous_baseline.absorbed_selective_backports`).
- New baseline: stable tag `rust-v0.172.0`,
  `3d86e43b075adeba2193ec5c22ac92f55afd82e6`; release branch base
  `39c29c3bb620f91e84a3bb266bb496dfb697c101`.
- Upstream range: 1,328 commits from `rust-v0.165.0`, 588 of them after the
  previously pinned `main` snapshot `c9b4267c`.
- Personal starting commit: `74060972db97a1c872be7dad87913fc7d3d65b19`.
- Development branch: `feature/upstream-0.172.0`.

Method: one three-way merge (base = renamed `rust-v0.165.0`, theirs = renamed
`rust-v0.172.0`, ours = xdcode `0.167.0`) instead of per-commit cherry-picks.
Both upstream trees were converted with `scripts/xdcode/rebrand.py` first. The
earlier selective backports are absorbed by the new baseline, so the same
regions are resolved once against their final upstream state. Generated
snapshots took the upstream side and are regenerated by tests; test-file
conflicts took upstream and restored xdcode-specific cases (shared provider
history across `-p`, daemon menu, provider selection, reconnect, async
compaction across provider switches).

## User decisions for this release

| Area | Decision |
| --- | --- |
| Version | Follow Codex: product `0.172.0` on `rust-v0.172.0`. |
| Delegation | Removed. `xdcode-delegate` skill, its guide routing and tests are deleted; `spawn_agent` catalog-ID provider routing and the v1 `selection` result are reverted to upstream. Catalog-aware effort validation for an inherited catalog model and service-default effort handling remain. |
| `tui_workspace` | Stable, enabled by default (upstream default). |
| `mcp_lazy_stdio_startup` | Stable, enabled by default (upstream default). |
| `xdcode exec --remote` | Removed (`--remote`, `--remote-auth-token-env`, `exec/src/remote.rs`). The root `--remote` is rejected for `exec` as before; interactive TUI `--remote` is unchanged. |
| `/rc` remote control | Not parseable or listed (`SlashCommand::is_supported`). |
| Voice / realtime / WebRTC | Unreachable: `/voice` is unsupported, the TUI start path refuses before touching audio (covers keymap and retry), and core `prepare_realtime_start` refuses start, attach and sideband streams. `voice-host` is not built or packaged. |
| Hosted Cloud paths new in this range | `xdcode tcp-tunnel` (Cloud portal gateway only) always errors; `tui_multi_backend`, which registers the hosted Cloud backend, is unavailable in xdcode. |

All other personal features listed in `AGENTS.md` are kept.

## Identity and network audit

Wire-level names that must stay as upstream defines them are preserved:
`codex/connection-lease`, `codex/connectionLease`, `codex/connection/open`,
`codex/connection/release`, `codex_rollout_budget_units`, `openai~1readOnly`.

New hosted hostnames in this range and their handling:

- `codex-portals.api.openai.com` (`tcp-tunnel`): subcommand disabled.
- `codex-cloud-backend.chatgpt.com` (`app-server-client` Cloud backend): only
  registered through `tui_multi_backend`, which xdcode makes unavailable.
- Regional `*.api.openai.com` / `chatgpt.com` hosts in
  `http-client/src/provider_endpoints.rs`: classification only (decides whether
  a destination is a hosted endpoint); no request is made to them by default.

Merge repairs worth knowing for the next upgrade: the three-way merge silently replaced
some xdcode behavior with upstream's (permission-aware host skill reads, `/resume` fork
lookups across all providers, `doctor` WebSocket endpoint details, test fixtures that
write an explicit local provider). When an xdcode-specific test fails after a merge,
diff the file against the pre-merge commit first.

Hosted/upstream surfaces that remain compiled in but unused by default (kept per the
user's "loose" policy): `exec-server --remote` registration, Cloud backend client code,
Gateway OAuth protocol types, analytics/feedback modules.
